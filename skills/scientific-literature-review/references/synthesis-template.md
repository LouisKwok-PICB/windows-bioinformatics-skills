# Literature Synthesis Template

Use this reference after candidate papers have been identified.

## Paper Extraction Table

| Field | What to record |
|---|---|
| Citation | First author, year, title, journal/preprint server, DOI/PMID/PMCID/arXiv/bioRxiv ID |
| Source status | abstract only, full text, PDF, supplementary data, dataset page |
| Biological or technical context | species, tissue, disease, assay, platform, model system |
| Main question | what the paper tested |
| Method or dataset | key method, cohort, data source, software, accession |
| Comparator/control | baseline, null model, control group, benchmark |
| Key result | result relevant to the current project |
| Evidence strength | direct evidence, proxy evidence, review statement, hypothesis, or unsupported claim |
| Limitations | sample size, platform, confounding, missing validation, restricted context |
| Use in project | background, method justification, comparator, limitation, discussion, do not use |

## Synthesis Pattern

Write synthesis around themes or evidence roles:

```text
Theme:
What is established:
What evidence supports it:
Where evidence disagrees:
What remains uncertain:
How this affects the current project:
Allowed manuscript use:
Forbidden overclaim:
```

## Evidence Language

- Use `reported`, `observed`, or `associated with` for descriptive or associational evidence.
- Use `supports` only when the paper's data directly address the claim.
- Use `suggests` for plausible but indirect evidence.
- Avoid `proves`, `drives`, `establishes mechanism`, or `is required for` unless causal or perturbational evidence supports it.

## Review Output Skeleton

```markdown
# Literature Review: [Topic]

## Question And Scope

## Search Strategy

## Included Evidence

## Theme 1: [Name]

## Theme 2: [Name]

## Methods/Dataset Lessons

## Limitations And Reviewer Risks

## Relevance To Current Project

## Source Table
```

Keep the active review concise. Put long article-by-article notes in an appendix or source table.
